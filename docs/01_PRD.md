# PRD — AI 기반 구직역량 진단·매칭 서비스

**상태**: Approved (조건부) — 비용 상한 확정 및 세그먼트 간 교차검증 필요
**작성 기준**: JTBD → VPS → MoSCoW → PRD 체인 (단계 1~7)

---

## 1. 제품 한 줄 정의

서류 탈락 원인을 모른 채 같은 이력서를 반복 수정하는 구직자에게, 학력·경력·자격증·skill 기반 100점 만점 점수와 항목별 감점 근거를 5분 안에 확인시켜 자신의 진짜 위치를 숫자로 확신하게 하는 서비스

---

## 2. 문제 정의·배경

구직자는 서류 지원 후 탈락 통보를 받아도 원인을 알 수 없어 같은 이력서·같은 지원 방식을 반복한다. 현재 이용 가능한 대안들은 이 문제를 해결하지 못한다:

- **무료 성향검사**: 성향 라벨만 제공할 뿐 직무 적합도나 감점 사유를 보여주지 않는다
- **스터디 카페·유튜브 피드백**: 발화자 본인도 같은 취준생이라 근거로 삼기 어렵다 ("이 정도면 괜찮을걸요" 수준)
- **유료 첨삭 서비스**: "돈 냈는데 또 애매한 답을 들으면 어떡하나"라는 이유로 회피 대상이 된다

> ⚠️ 위 Pain·대안 분석은 **청년(무경력 구직 초년생) 세그먼트 인터뷰 1건**에 기반합니다. 경력단절여성·중장년 경력전환 세그먼트에서도 동일하게 나타나는지는 **확인 필요**.

---

## 3. 목표 사용자 · User Story

**목표 사용자**: 자신의 역량이 희망 직무 대비 어느 수준인지 객관적 근거 없이 판단한 채, 같은 방식(지원/이력서 수정)을 반복하며 탈락을 겪는 구직자 (경력단절여성 재취업 희망자 / 무경력 구직 초년생 / 중장년 경력전환 희망자 3개 세그먼트 공통 지향)

**User Story**:
> 구직자로서, 학력·경력·자격증·skill을 근거로 희망 직무 대비 현재 역량을 100점 만점 점수로 확인하고 싶다. 왜냐하면 내가 뭘 몰라서 떨어지는 게 아니라는 확신을 얻고 싶기 때문이다.

사회적 Job 기반 User Story: 확인 필요 (근거 부족으로 미도출)

---

## 4. 가치제안 (VPS 요약)

- **Value Proposition**: 서류 탈락 원인을 모른 채 같은 이력서를 반복 수정하는 구직자가, 근거 없는 성향검사나 주관적 스터디 카페 피드백 대신 — 학력·경력·자격증·skill 기반 100점 만점 점수와 항목별 감점 근거를 5분 안에 확인해, 자신의 진짜 위치를 숫자로 확신하게 한다.
- **Differential Value (Resonating Focus, 1개로 압축)**: 성향이 아니라 **항목별 근거가 있는 직무 적합도 점수**를 제공한다는 점
- **Proof**: 현재 **행동 증거 없음** — 인터뷰 발화("면접까지도 못 가는데 뭐가 문제인지 아무도 안 알려줘요")만 확보된 상태. 선주문·지불의사 등 실측 데이터는 미수집.

---

## 5. 기능 목록 + Acceptance Criteria

### [Must] 입력 폼 + 진단 점수 산출 엔진

| 구분 | 시나리오 |
|---|---|
| 정상 1 | Given 필수 항목(학력·나이·경력) 입력 및 자격증·skill 입력(보유 항목이 없으면 "없음"으로 입력 가능) → When "진단하기" 클릭 → Then 5초 이내 100점 만점 점수 표시 |
| 정상 2 | Given 동일 입력값 재제출 → When 진단 재실행 → Then 동일 점수 산출 (재현 가능성 보장) |
| 실패 1 | Given 필수 항목(학력·나이·경력) 누락 → When "진단하기" 클릭 → Then 점수 미산출, 누락 항목 명시한 오류 메시지 표시 |

> 📝 **수정 이력(2026-09-19)**: 정상 시나리오 1의 "모두 입력"이 실패 시나리오 1의 필수 항목 범위(학력·나이·경력)와 모순되어 있었음(SRS 검토 §12-C2). 자격증·skill은 선택 입력이며 보유 항목이 없을 경우 "없음"으로 입력해 진단을 진행할 수 있도록 명확화함. 필수 항목은 학력·나이·경력 3개로 유지.

### [Must] 항목별 감점 근거 상세 화면

| 구분 | 시나리오 |
|---|---|
| 정상 1 | Given 점수 산출 완료 → When "근거 보기" 클릭 → Then 학력/경력/자격증/skill 항목별 감점 사유 최소 3개 이상 표시 |
| 정상 2 | Given 특정 항목 만점 → When 근거 화면 열람 → Then 해당 항목 "감점 없음"으로 명확히 구분 표시 |
| 실패 1 | Given 진단 미완료 상태 → When 근거 화면 접근 시도 → Then "먼저 진단을 완료해주세요" 안내로 이동 |

### [Should] 자격증·훈련 추천 리스트

기능: 감점 항목 기반 자격증·직업훈련 과정 추천 (룰 기반 정적 매핑)

### [Should] 자격증·훈련 추천 개인화 알고리즘 *(예외적으로 In Scope 편입)*

기능: 사용자 진단 점수 프로필(감점 항목 조합)에 따라 추천 우선순위를 다르게 매기는 **룰 기반** 로직 (머신러닝 아님)

> ⚠️ **편입 경위**: 이 기능은 AOS/DOS 재채점·게이트 통과 절차 없이, 사용자 요청에 따라 Out of Scope에서 In Scope(Should)로 예외적으로 편입되었습니다. VPS Differential Value(1개로 좁힌 항목)에도 해당하지 않습니다.

| 구분 | 시나리오 |
|---|---|
| 정상 1 | Given 두 사용자의 감점 항목 조합이 다름(A: 자격증 부족, B: 경력 부족) → When 각각 추천 리스트 확인 → Then 서로 다른 우선순위 추천 표시 |
| 정상 2 | Given 동일 감점 조합으로 재진단 → When 추천 리스트 재확인 → Then 동일 우선순위 결과 재현 |
| 실패 1 | Given 감점 항목 없음(만점) → When 추천 리스트 접근 → Then "보완이 필요한 항목이 없습니다" 안내로 대체 |

### [Could — Out of Scope] 무료 진단 → 유료 전환 구조
지불 의향 미실측 상태로 이번 범위에서 설계하지 않음

## 6. KPI

> ⚠️ VPS Proof가 "행동 증거 없음" 상태이므로, 아래 수치는 **검증된 근거가 아니라 가설적 목표**이며 실제 근거는 사용자 테스트 이후 확보 필요.

- **북극성 KPI**: 진단 완료 후 근거 화면 도달 비율 — 목표 70% 이상 (가설)
- **보조 KPI 1**: 입력 시작~점수 확인 소요 시간 — 목표 5분 이내
- **보조 KPI 2**: 진단 1회당 표시되는 감점 근거 개수 — 목표 3개 이상
- **실패 KPI(피봇 기준)**: 근거 화면 이탈률 50% 초과, 또는 4주 내 재방문(재진단) 비율 10% 미만 시 → Pain/Job 정의 재검토

> 개인화 알고리즘(Should)에 대응하는 KPI는 현재 없음 — 별도 정의 필요.

---

## 7. 비기능 요구사항

- **성능**: 점수 산출 응답 시간 5초 이내
- **안정성**: 초기 베타 기준 가동률 95% 이상
- **보안**: 학력·경력·자격증 등 개인식별정보 암호화 저장, 제3자 무단 접근 차단
- **비용**: 1인 개발 + 무료/저비용 툴 한도 내 운영 — **구체적 월 비용 상한은 확인 필요**

---

## 8. 제약 조건

- 1인 개발 체제 — 복잡한 서버 인프라·유료 API 의존 최소화
- 베타 테스트는 무료/저비용 도구로만 진행
- 지불 전환 관련 기능은 이번 범위에서 설계하지 않음
- 개인화 알고리즘은 머신러닝이 아닌 **룰 기반 매핑 로직**으로 한정

---

## 9. Out of Scope

| 항목 | 제외 사유 | 재검토 시점 |
|---|---|---|
| 무료→유료 전환/과금 구조 | 지불 의향 미실측, 설계 근거 부족 | 사용자 테스트로 지불 의향 확인 후 |
| 채용공고 매칭/추천 | VPS·MoSCoW에 근거 없음 | 별도 Desired Outcome 도출 필요 시 |
| 커뮤니티/스터디 기능 | 근거 없음 | 별도 검증 필요 시 |
| 사회적 Job 기반 기능 | VPS에서 사회적 Job 자체가 확인 필요 상태 | 사회적 Job 근거 확보 후 |

## 10. 알려진 리스크 · 열린 질문 (체인 정합성 점검 결과)

개발 착수 전 반드시 인지하고 있어야 할 사항:

1. **세그먼트 검증 격차**: 핵심 Job·Pain은 청년 세그먼트 인터뷰 1건에서만 도출됨. "3세그먼트 통합 서비스"를 지향하지만 경력단절여성·중장년 세그먼트에서 동일 패턴이 나타나는지 확인 불가.
2. **개인화 알고리즘의 방법론적 예외**: 다른 Must 기능과 달리 AOS/DOS 재채점·게이트 검증 없이 편입됨. 또한 VPS가 정식 차별점으로 인정하지 않은 영역(Differential Value 1개로 좁혀짐)까지 기능 범위가 확장된 상태.
3. **Proof 공백**: VPS의 행동 증거가 전무한 상태로 KPI 목표치가 설정됨 — 전부 가설.
4. **비용 상한 미확정** — DoD 비기능 수치화 항목 부분 통과 사유.

**개발 착수 전 권장 조치**:
- Must 2개 기능을 다른 세그먼트(경력단절여성 또는 중장년) 최소 1명과 짧게 검증
- 개인화 알고리즘 KPI 별도 정의
- 월 비용 상한 확정
