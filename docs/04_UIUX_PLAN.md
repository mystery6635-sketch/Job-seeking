# UI/UX Plan — AI 기반 구직역량 진단·매칭 서비스 (v1 MVP)

**기반 문서**: `docs/01_PRD.md`, `docs/02_SRS_BASELINE.md`, `docs/PROJECT_SCOPE.md`, `docs/03_UI_COVERAGE_ANALYSIS.md`, `design-reference/vendor/apple/DESIGN-apple.md`

본 문서는 Apple 스타일 참고본에서 타이포그래피 절제·단일 액센트 컬러·여백 리듬 등 **구조적 원칙만** 차용하고, Apple 상표(SF Pro, 로고, 사과 모양, "Apple" 관련 표현)는 사용하지 않는다. 화면은 `docs/03_UI_COVERAGE_ANALYSIS.md`에서 고정한 3개 Screen(SCR-001~003)을 그대로 사용한다.

---

## 1. 공통 디자인

- **브랜드명**: JobFit (구직역량 진단 서비스)
- Apple 스타일은 여백 리듬·단일 액센트 컬러·절제된 타이포그래피만 참고하고, 상표 요소(로고·서체명·문구)는 사용하지 않는다.
- **배경**: 흰색(`#ffffff`) 기본, **텍스트**: 짙은 회색(`#1d1d1f`)
- **포인트 컬러**: 코랄(`#ff6f59`) — 진단 CTA, 강조 링크, 선택 상태에 사용하는 단일 액센트
- **폰트**: 한글 본문은 Inter(Google Fonts)와 시스템 한글 폰트(Apple SD Gothic Neo, Malgun Gothic, sans-serif) fallback을 사용한다.
- **Header/Footer**: SCR-001~003 3개 화면에서 공통 컴포넌트로 사용한다.
  - Header: 좌측 JobFit 로고/워드마크, 우측 "진단 시작하기"(코랄 버튼, 항상 노출)
  - Footer: 서비스 소개 한 줄, 이용안내·개인정보 처리방침 링크, 저작권 표기
- **기준 해상도**: Desktop 1440px, Mobile 390px
- **Semantic Color**: 코랄 포인트와 구분되는 색을 오류/경고/안내에 사용한다.
  - 오류(필수 항목 누락 등): 레드 계열 `#d92d20`
  - 경고(진단 미완료 접근 등): 앰버 계열 `#b54708`
  - 안내/정보(대체 안내, Empty State): 뉴트럴 블루 `#175cd3`
- **접근성**: 모든 인터랙티브 요소에 키보드 포커스 링(2px solid 코랄)을 두고, 버튼·입력 필드는 44px 이상의 터치 영역을 확보한다.

## 2. 콘텐츠 밀도와 섹션 배치 규칙

- 모든 화면은 Header와 Footer 사이에 목적이 분명한 콘텐츠 Section을 순서대로 배치한다.
- **SCR-001(진단 입력)은 5개 Section**, **SCR-002(진단 결과)는 6개 Section**, **SCR-003(추천 리스트)은 5개 Section**, **SCR-004(구인정보 검색 연결)은 4개 Section**, **SCR-005(MBTI 태도 지표)은 4개 Section**을 기본으로 한다.
- Desktop 콘텐츠 최대 폭은 1200~1280px, Section 상하 여백은 64~96px 범위로 설계한다.
- Mobile Section 상하 여백은 40~64px 범위로 줄이고 Card·입력 필드를 1열로 배치한다.
- Hero(입력 폼 상단)가 첫 화면 전체 높이를 차지하지 않게 하며, 1440px 화면에서 다음 Section의 시작이 보이게 한다.
- 각 Section에는 제목, 1~3문장의 설명, 실제 입력/결과 콘텐츠 또는 명확한 CTA를 둔다.
- Hero, Form Card, 좌우 분할(점수+요약), Chip 목록(감점 항목 태그), 3단계 안내, CTA Banner를 교차 사용해 같은 Card만 반복하지 않는다.
- Lorem ipsum, `준비 중`, `정보 확인 필요`, 의미 없는 빈 Card와 과도한 빈 여백을 남기지 않는다.
- 감점 항목이 없거나(만점) 추천 대상이 없는 상태도 안내 문장, 다음 행동 CTA를 함께 표시해 빈 화면처럼 보이지 않게 한다.
- 제목과 설명은 자연스러운 한국어 완성 문장으로 쓴다.

## 3. SCR-001 `/diagnosis` 진단 입력

1. **Hero**: "5분 안에 내 구직역량을 숫자로 확인하세요" 헤드라인 + 1~2문장 설명 + 화면 하단 입력 폼으로 스크롤 유도 CTA. 전체 높이를 차지하지 않고 다음 Section 상단이 보이도록 구성한다.
2. **필수 정보 입력 Form**: 학력·나이·경력 입력 필드(각 필드에 예시 placeholder), 미입력 시 필드 하단에 레드 계열 오류 메시지 표시
3. **선택 정보 입력 Form**: 자격증·skill 입력 필드(태그/Chip 입력), 보유 항목이 없으면 "없음" 선택 가능한 토글 또는 체크박스
4. **진단 안내 3단계**: "정보 입력 → 점수 확인 → 감점 근거·추천 확인" 3단계 아이콘 안내 Section
5. **제출 CTA Banner**: "진단하기" 코랄 버튼(제출 중 비활성화 상태 포함), 아래에 "입력하신 정보는 진단 목적으로만 사용됩니다" 개인정보 안내 1문장

- **상태**: 초기 입력 / 필수 항목 오류(레드 메시지) / 제출 중(버튼 비활성화, 로딩 인디케이터) / 제출 완료(SCR-002로 이동)
- Card만 반복하지 않도록 Hero → Form Card → Form Card → 3단계 안내(아이콘형) → CTA Banner 순서로 교차 배치한다.

## 4. SCR-002 `/diagnosis/result` 진단 결과 (감점 근거 Drawer/Modal 포함)

1. **결과 Hero**: 100점 만점 총점을 큰 숫자로 표시, 점수에 대한 1~2문장 코멘트(예: "학력·경력 대비 상위 구간입니다" 등 점수 구간별 안내 문구)
2. **좌우 분할 요약 Section**: 좌측 점수 게이지/도넛 표시, 우측 입력값 요약(학력·나이·경력·자격증·skill 재표시)
3. **감점 근거 진입 Section**: "근거 보기" CTA와 감점 항목 수 미리보기(Chip 형태), 클릭 시 같은 화면에서 Drawer/Modal이 열려 항목별 감점 사유(최소 3개)와 만점 항목의 "감점 없음" 표시를 보여준다.
4. **감점 항목 Chip 목록**: 학력/경력/자격증/skill 카테고리별 상태를 Chip으로 요약 표시(감점 있음/감점 없음 색상 구분)
5. **추천 리스트 이동 CTA Banner**: "감점 항목 기반 추천을 확인해 보세요" 문구와 SCR-003으로 이동하는 코랄 버튼
6. **재진단 안내**: "다른 정보로 다시 진단하기" 링크(SCR-001로 이동) 및 재현성 안내 1문장

- **상태**: 결과 로딩 / 결과 표시 / 진단 미완료 접근 시 경고 안내(앰버 계열, "먼저 진단을 완료해주세요" + SCR-001 이동 CTA) / Drawer 열림·닫힘
- Hero(점수) → 좌우 분할(게이지+요약) → CTA형 Section(근거 보기) → Chip 목록 → CTA Banner(추천 이동) → 텍스트 링크형 Section 순서로 같은 형태의 반복을 피한다.

## 5. SCR-003 `/diagnosis/result/recommendations` 추천 리스트

1. **Intro**: "감점 항목을 보완할 수 있는 자격증·훈련 과정을 확인하세요" 설명과 이용 방법 1~2문장
2. **추천 Card Grid**: 감점 항목별 추천 자격증·훈련 과정 Card(제목, 관련 감점 항목 태그, 외부 정보 링크가 있다면 alt 텍스트를 갖춘 이미지 포함)
3. **감점 항목 없음 Empty State**: 만점인 경우 "보완이 필요한 항목이 없습니다" 안내 문장 + 축하 메시지 + SCR-002로 돌아가는 CTA를 함께 표시(빈 화면으로 보이지 않게 구성)
4. **추천 활용 3단계 안내**: "추천 확인 → 관심 과정 탐색 → 신청/학습 시작" 3단계 안내 Section
5. **CTA Banner**: "다시 진단하기" 및 "결과로 돌아가기" 두 개의 이동 CTA

- **상태**: 추천 목록 표시(정적 매핑) / 대체 안내 표시(만점, Empty State) / 진단 미완료 접근 시 경고 안내(SCR-002와 동일한 경고 패턴 재사용)
- Card Grid와 Empty State는 상호 배타적으로 노출하며, 두 상태 모두 3단계 안내·CTA Banner Section을 공통으로 유지해 화면 구조 일관성을 유지한다.

## 6. SCR-004 `/diagnosis/result/jobs` 희망 직무 기반 외부 구인정보 검색 연결

> 2026-10-03 사용자 요청으로 추가된 화면. 매칭·추천 알고리즘은 포함하지 않으며(`docs/02_SRS_BASELINE.md` OS-03 범위 경계 참조), 입력된 희망 직무 문자열을 사이트별 검색 URL에 그대로 전달하는 단순 링크 연결만 제공한다.

1. **Intro**: "희망 직무로 구인 사이트를 바로 검색해보세요" 제목과 "진단 시 입력하신 희망 직무를 기준으로 주요 채용 사이트의 검색 결과로 바로 이동할 수 있습니다. 특정 공고를 추천하지는 않습니다" 설명
2. **구인 사이트 연결 Card Grid**: 잡코리아, 사람인, 원티드, 워크넷, IT 전문 구인 사이트(예: 프로그래머스 잡, 로켓펀치) 등 사이트별 Card(로고/이름, 1문장 사이트 소개, "희망 직무로 검색하기" 코랄 버튼 — 클릭 시 새 탭으로 각 사이트의 해당 희망 직무 검색 결과 페이지 이동)
3. **희망 직무 없음 Empty State**: 희망 직무 정보가 없는 경우 "희망 직무를 입력하면 관련 채용 사이트를 바로 연결해 드립니다" 안내 문장과 진단 화면(SCR-001)으로 돌아가는 CTA
4. **CTA Banner**: "진단 결과로 돌아가기"(SCR-002) 링크와 "다시 진단하기"(SCR-001) 링크

- **상태**: 연결 Card 목록 표시 / 희망 직무 없음 Empty State / 진단 미완료 접근 시 SCR-002·SCR-003과 동일한 경고 패턴 재사용
- Card Grid는 외부 링크임을 명확히 하기 위해 각 버튼에 외부 이동 아이콘을 표기하고, "입력하신 희망 직무 정보는 검색창 채움 용도로만 사용되며 특정 공고를 추천하지 않습니다"라는 1문장을 Section 하단에 덧붙인다.

## 7. SCR-005 `/diagnosis/attitude` MBTI 기반 직무 수행 태도 보조 지표

> 2026-10-03 사용자 요청으로 추가된 화면. PRD §4의 핵심 차별화 문구("성향이 아니라 근거 있는 직무 적합도 점수")와 충돌하지 않도록, 본 화면의 점수는 핵심 역량 100점 점수와 **절대 합산·혼용하지 않는 별개의 참고용 보조 지표**로 명확히 분리 표기한다(`docs/02_SRS_BASELINE.md` IS-07 리스크 노트 참조).

1. **Intro**: "내 MBTI로 직무 수행 태도를 참고해보세요"라는 제목과 "이 점수는 참고용 보조 지표이며, 핵심 역량 진단 100점 점수에는 반영되지 않습니다"라는 설명 — 고지 문구는 코랄이 아닌 info 색(뉴트럴 블루)으로 시각적으로도 핵심 점수와 구분한다.
2. **MBTI 16유형 선택 Section**: 4열×4행 Chip/Card 그리드(INTJ, ENFP 등 16유형), 선택 시 해당 Chip만 강조 표시
3. **태도 점수·설명 Section**(선택 후 노출): 선택 유형의 직무 수행 태도 점수(정성 구간 배지, 예: "협업 적합도 상"), 강점 2~3개, 유의점 1~2개를 좌우 분할 또는 리스트로 표시. 섹션 상단에 "참고용 보조 지표" 배지를 재노출
4. **CTA Banner**: "핵심 역량 진단 시작하기"(코랄/블루 CTA, SCR-001 이동)와 "다른 유형으로 다시 보기"(텍스트 링크)

- **상태**: MBTI 미선택 안내 상태(선택 Chip 그리드만 노출, 설명 Section 숨김) / 선택 완료 결과 표시 상태
- MBTI 미선택 Empty State에도 "내 MBTI를 선택하면 직무 수행 태도 보조 지표를 확인할 수 있습니다"라는 안내와 선택 그리드를 함께 제공해 빈 화면으로 보이지 않게 한다.

- 로그인/계정/관리자 관련 Unauthorized 상태는 v1 범위 밖(OS-06, OS-07)이므로 정의하지 않는다.

## 9. 검사 결과

- `docs/03_UI_COVERAGE_ANALYSIS.md`의 5개 고정 Screen(SCR-001~005) 구조를 그대로 유지했으며, 지침에 없는 화면을 추가로 만들지 않았다.
- EXCLUDED 요구사항(REQ-FUNC-PERSONALIZE-001~003, REQ-FUNC-ADMIN, REQ-NFR-AVAIL-001, REQ-NFR-PRIV-002)에 대응하는 UI는 어떤 Section에도 배치하지 않았다.
- SCR-004는 매칭·추천 알고리즘 없이 외부 검색 링크만 제공하도록 설계해 OS-03(채용공고 매칭·추천 제외)과 충돌하지 않게 했다.
- SCR-005는 PRD §4 차별화 문구와의 충돌을 피하기 위해 핵심 100점 점수와 절대 합산하지 않는 참고용 보조 지표로 시각적·문구적으로 분리했다.
- Apple 스타일 참고본에서는 여백 리듬·타이포그래피 절제·단일 액센트 컬러 원칙만 인용했고, 색상·서체명·상표 요소는 그대로 사용하지 않았다.
