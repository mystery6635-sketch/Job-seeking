# PROJECT_SCOPE — AI 기반 구직역량 진단·매칭 서비스 (v1 MVP)

**기반 문서**: `docs/01_PRD.md`, `docs/02_SRS_BASELINE.md`, 현재 `package.json`/`src/app` 구조
**현재 코드 상태**: Next.js 기본 스캐폴드(`create-next-app`)만 존재, 기능 코드 없음

## 요구사항 상태 정의

- **IMPLEMENT**: 구현하고 테스트
- **EXCLUDED**: 만들지 않으며 제외 이유를 기록

## 1. 반드시 직접 구현할 범위

1. 핵심 화면 3개(`/diagnosis`, `/diagnosis/result`, `/diagnosis/result/reasons`)와 보조 화면 1개(`/diagnosis/result/recommendations`)
2. 학력·나이·경력(필수) + 자격증·skill(선택, 미보유 시 "없음") 입력 폼과 검증
3. 100점 만점 진단 점수 산출 엔진(결정적 로직, 재현 가능)
4. 항목별 감점 근거 상세 화면(최소 3개 이상, 만점 항목은 "감점 없음" 표시)
5. 진단 미완료 시 근거/추천 화면 접근 차단 및 안내
6. 자격증·훈련 추천 리스트(코드 내 하드코딩 Dummy 정적 매핑, 개인화 없음)
7. 진단 제출 중복 방지(제출 중 버튼 비활성화)
8. 개인식별정보(학력·경력·자격증 등) 암호화 저장 및 접근 제어
9. 개인정보 접근 이력·KPI 이벤트(진단 완료, 근거 화면 도달)의 최소 로깅
10. 희망 직무 기반 외부 구인정보 검색 연결 화면(SCR-004, `/diagnosis/result/jobs`): 잡코리아·사람인·원티드·워크넷·IT 전문 구인 사이트 등으로 새 탭 연결(매칭·추천 알고리즘 없음)
11. MBTI 기반 직무 수행 태도 보조 지표 화면(SCR-005, `/diagnosis/attitude`): 16유형 선택 → 정적 매핑 기반 태도 점수·강점·유의점 표시. **핵심 역량 100점 점수와 분리된 참고용 지표**이며 합산하지 않음
12. Playwright 핵심 Smoke Test
13. Vercel 배포

## 2. 구현 방식

- 진단 입력값·점수·감점근거·추천 결과는 세션 단위로 관리하며, 계정/로그인 엔터티는 만들지 않는다(v1은 인증 미포함)
- 채점 가중치·감점 사유 로직은 코드 내 결정적 룰 기반 함수로 구현한다(머신러닝 아님)
- 자격증·훈련 추천 매핑은 `src/data` 정적 데이터(하드코딩 소규모 테이블)로 구현하고 외부 데이터 연동은 하지 않는다
- 진단 결과 재조회는 `result_id` 기반으로 하고, 별도 이력 목록·수정 기능은 만들지 않는다
- 개인정보 암호화는 사용하는 관리형 DB(예: Supabase/Postgres)의 기본 저장 암호화 기능을 활용하고, 별도 커스텀 암호화 계층은 만들지 않는다
- 접근 로그·KPI 로깅은 호스팅/DB 기본 로그와 무료 분석 도구로 대체한다(커스텀 감사 로그 시스템 없음)
- 진단 제출 중복 방지는 클라이언트 버튼 비활성화 수준으로 한정하고, 서버 측 멱등키 처리는 만들지 않는다
- 외부 구인 사이트 연결은 사이트별 검색 URL 템플릿에 희망 직무 문자열을 치환해 넣는 수준으로 구현하고, 공고를 선별·정렬·추천하는 로직은 만들지 않는다(OS-03과의 경계는 `docs/02_SRS_BASELINE.md` §1.2.2 참조)
- MBTI 기반 직무 수행 태도 지표는 16유형 → (태도 점수, 강점, 유의점) `src/data` 정적 매핑 테이블 조회만 수행하고, 머신러닝·개인화 로직은 만들지 않는다. 화면 어디에서도 핵심 역량 100점 점수와 합산·가중평균하지 않으며, 참고용 보조 지표임을 상시 고지한다(PRD §4 차별화 문구와의 경계는 `docs/02_SRS_BASELINE.md` IS-07 리스크 노트 참조)
- 관리자/운영자 전용 화면은 만들지 않으며, 운영자 조치(수동 삭제 등)는 DB 콘솔에서 직접 수행한다
- 성능(5초 이내 응답)과 베타 가동률(95%)은 수동 측정으로 확인하고, 정식 부하테스트·모니터링 인프라는 만들지 않는다

## 3. 제외 기능

- 무료 진단 → 유료 전환 구조 (지불 의향 미실측)
- 채용공고 매칭·추천 (VPS·MoSCoW 근거 없음)
- 커뮤니티/스터디 기능 (근거 없음)
- 사회적 Job 기반 기능 (VPS에서 근거 자체가 확인 필요 상태)
- 추천 개인화 알고리즘 (PRD §10-2가 게이트 통과 없이 예외 편입되었음을 스스로 명시, Post-MVP 이연)
- 로그인/인증 위임 (v1의 어떤 기능도 로그인을 전제하지 않음)
- 관리자/운영자 전용 화면 (PRD 근거 없음)
- 진단 데이터 정식 자동 보존·삭제 정책 및 자동화 (보존기간 미정, v1은 운영자 수동 처리)
- 정식 감사 로그·모니터링 인프라, 부하테스트
- 서버 측 정식 멱등키 처리(중복 제출 방어 고도화)

## 5. 검사 결과

- SRS §4.3~4.4에 정의된 모든 Requirement ID(REQ-FUNC-DIAG-001~004, REQ-FUNC-SCORE-001~003, REQ-FUNC-RECO-001, REQ-FUNC-JOBLINK-001~002, REQ-FUNC-ATTITUDE-001~002, REQ-FUNC-PERSONALIZE-001~003, REQ-FUNC-ADMIN, REQ-NFR-PERF-001, REQ-NFR-AVAIL-001, REQ-NFR-SEC-001~003, REQ-NFR-PRIV-001~002, REQ-NFR-OBS-001)를 한 번씩 모두 기록했다.
- 삭제된 Requirement는 없다. Post-MVP·범위 밖 항목은 EXCLUDED로 표시하고 사유를 남겼다.
- REQ-FUNC-JOBLINK-001~002는 2026-10-03 사용자 요청으로 신규 편입되었으며, OS-03(채용공고 매칭·추천 제외)과 충돌하지 않도록 "매칭·추천 없는 단순 외부 검색 링크"로 범위를 한정했다(`docs/02_SRS_BASELINE.md` §1.2.2 참조).
- REQ-FUNC-ATTITUDE-001~002도 2026-10-03 사용자 요청으로 신규 편입되었다. PRD §4의 핵심 차별화 문구("성향이 아니라 근거 있는 점수")와 충돌 소지가 있어, 핵심 100점 점수와 **절대 합산하지 않는 별개의 참고용 보조 지표**로 범위를 한정하고 리스크로 기록했다(`docs/02_SRS_BASELINE.md` §1.2.1 IS-07, §7 OQ-23 참조).
